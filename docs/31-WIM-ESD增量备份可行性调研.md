# WIM/ESD 增量备份可行性调研（2026-10-28）

> 需求：用户希望"增量备份"——第二次备份只写变化的部分，省时间省空间。
> 状态：**调研 + 本机实测**（结论已用真实数据支撑）。

## 1. 结论摘要（先看这段）

1. **WIM 的"多镜像追加"（append）本身就是文件级去重快照**：同一个文件在多个子镜像之间
   **只存一份**，所以第二次备份只增长"**变更文件的全量 + 元数据**"。
   我们的 CLI **已经支持**（`backup --append`），只是还没在 GUI 上暴露、也没写清语义。
2. **它不是块级增量**：**改动一个文件里的 1 个字节，也要把整个文件重新存一遍**。
   所以：**大量小文件 + 少量变更**（Windows 系统盘典型）→ 省得很多；
   **大文件小改动**（VHD / 数据库 / ISO）→ 几乎不省，甚至"追加"比"重新全备一份"还占空间（旧版本都留着）。
3. **ESD（solid / LZMS）也支持 append**：实测把 8MB 文件改掉后追加，**+8.39MB / 1.7s**（不是整包重写）。
4. 建议：
   - **P0（低成本，马上做）**：把 `--append` 产品化为「**增量备份（多时间点）**」——
     GUI 加一个勾选、命名 `Backup (2)`、**空间预估 = 变更文件总大小 ×1.1 + 元数据**、
     还原时用现有 `--index` 选时间点。同时写清"不是块级增量"。
   - **P1（按需）**：真正的"文件级 delta 链"（自有格式）——见 §5，成本明显高，先不做。

## 2. 实测数据（本机，0.9.50，真实 wimlib 1.14.5）

### 2.1 大文件场景（2 × 8MB 随机数据）

| 步骤 | 产物大小 | 说明 |
|---|---|---|
| 首次 `backup --compress fast` | 16,778,840 B | 16MB 随机数据（几乎不可压） |
| 改 `big2.bin`（整文件重写）+ 新增 `big3.bin`（8MB），`--append` | **33,558,413 B（+16,778,000）** | 只多了"变了的 big2 + 新的 big3"，**big1 共享未重复** |
| `images` | `1 Backup` / `2 Backup (2)` | 两个时间点都在 |

**解读**：文件级去重确实生效（big1 没重复存），但**变了的 8MB 文件是整份重存**。

### 2.2 典型系统盘场景（300 × 64KB 小文件，改 3 个）

| 步骤 | 产物大小 | 增量 |
|---|---|---|
| 首次 `backup --compress fast` | 19,687,462 B（原始 19.2MB，元数据约 487KB） | — |
| 改 3 个文件（196,608 B），`--append` | 19,911,826 B | **+224,364 B** |
| 对照：对改动后的目录**全新全备** | 19,687,616 B | — |

**解读**：增量成本 ≈ 变更数据 + **约 28KB 的元数据**；此时"追加"总量（19.91MB）
略大于"重新全备"（19.69MB）——**因为追加保留了旧版本**。这就是"多时间点 vs 只留最新"的取舍。

### 2.3 ESD / solid（LZMS）能不能追加？

| 步骤 | 产物大小 | 耗时 |
|---|---|---|
| 首次 `backup --compress recovery`（ESD） | 25,167,426 B | 6 s |
| 内容**未变**再 append（同源） | 25,169,576 B | <1 s（**+2,150 B**，全部去重，只剩元数据） |
| 改 8MB 文件后 append | 33,561,208 B | **1.7 s**（+8.39MB） |

**解读**：wimlib **支持对 solid WIM 追加**，且不是"整包重压"（8MB 变更只花 1.7s）。
⚠️ 这一条对"ESD 不能增量"的常见说法是个反例——但要长期用仍建议：**增量链用 `.wim`（fast/maximum），
最终归档再转 `.esd`**（转格式需要重写，属离线动作）。

## 3. 机制：为什么是"文件级"而不是"块级"

- WIM 把每个文件内容存成按 SHA-1 命名的 **blob**；多个子镜像引用同一 blob → 相同文件只存一份。
- **blob 的最小单位是"整个文件"**：文件内容变 1 字节 → 新 blob，旧的仍被历史镜像引用 → 两份都留。
  所以"文件级去重"省的是"**未变更的文件**"，不是"文件内的未变更字节"。
- 每个子镜像都存一份**目录树元数据**（路径/属性/时间/ACL/EA/reparse 等）→ 文件越多，每次追加的固定成本越大
  （本次 300 文件 ≈ 28KB；真实系统盘 30 万文件会明显更大，需实测）。
- ESD = 每个子镜像一组 **solid 压缩块**（LZMS 高压缩）；追加只新增"新镜像的 solid 组"。

## 4. 适用性判断（给用户看的实话）

| 场景 | 是否值得用 append | 原因 |
|---|---|---|
| Windows 系统盘日常快照（隔几天一次） | ✅ 很划算 | 变化文件占比小（DLL/日志/用户文件），未变文件全共享 |
| 打补丁 / 装软件后备份 | ✅ 划算 | 变更集相对整盘很小 |
| 大文件为主（VHD/数据库/镜像文件） | ❌ 不划算 | 改一点就整文件重存，旧版本还留着 |
| 需要"只保留最新一份" | ❌ 用全新全备 | 追加会**累积历史**，总量只增不减 |
| 需要"回到某一天" | ✅ 正好 | 每个子镜像就是一个时间点，`--index` 选 |

**空间公式（经验）**：`追加增量 ≈ Σ(变更文件原始大小) × 压缩比倒数 + 元数据(文件数 × 0.1~2KB)`
（`fast` 压缩对已压缩内容≈1:1；`recovery` 视内容而定）。

## 5. P1：真正的"文件级 delta 链"（如果 P0 不够）

设计草案（**不是块级 dedup**）：

```
base.esd          第 1 次全备（现状）
d-20261028.zjd    delta：{manifest(diff) + 变更文件 blob + 删除列表}
```

- manifest：每条 `{相对路径, 大小, mtime, SHA-256, 属性/ACL/EA/reparse 摘要}`；
  与 base 的 manifest 做差 → `新增/修改/删除` 三类。
- 还原：`apply(base)` → 再 `apply(delta)`（覆盖新增/修改、按删除列表删文件）。
  **复用现有能力**：Windows 侧（A 引擎/PE）直接解压 delta 即可；
  Linux 侧（B 引擎）要靠与 ZJEA 同款的"投放 + 首启补写"机制处理 EA/重解析点（现成资产）。
- 成本：delta 生成要做**全盘哈希**（30 万文件 ≈ 数分钟，和现在备份的扫描阶段同量级）；
  删除列表/重命名要小心（重命名会被当成删+增，除非加"同哈希文件"识别）。
- **不做块级 dedup**：需要类似 VSS 写入跟踪/块哈希索引，复杂度和风险不成比例；
  真要块级，业界做法是 VHDX differencing 或 ReFS 快照，那是另一个产品形态。

## 6. 建议的落地顺序

1. **P0（建议本轮之后做，量小）**
   - GUI 备份模式加「增量追加（多时间点）」勾选（`--append` 已有，接线即可）；
   - 文件名/子镜像名沿用 `Backup (N)`，UI 显示"共 N 个时间点 / 合计 X GB"；
   - 还原时镜像下拉已能列 `1..N`（`images` 已支持），补一句"选哪个时间点"；
   - **空间预估**：先估算"变更文件总量"（备份扫描阶段已有清单），不足则提示"建议改用全新全备"；
   - 文档写清"文件级去重，不是块级增量"。
2. **P1（按需）**：delta 链（§5），只在"客户确实需要每天快照且系统盘文件数不大"时做。
3. **配套**：`docs/28`（打开文件处理）与本文互相引用 —— 跳过不可读文件时，
   增量快照里该文件"沿用上一版"，需要在 manifest 里记录（P0 先简单：跳过=不写该文件）。

## 7. 实测命令（可复现）

```powershell
# 大文件场景
.\dist\x64\SysRecover.exe backup --dest D:\ea-lab\inc-test\a.wim --source D:\ea-lab\inc-test\src `
    --compress fast --no-snapshot --yes
# 改动后追加
.\dist\x64\SysRecover.exe backup --dest D:\ea-lab\inc-test\a.wim --source D:\ea-lab\inc-test\src `
    --compress fast --no-snapshot --append --yes
.\dist\x64\SysRecover.exe images --file D:\ea-lab\inc-test\a.wim
# ESD（solid）追加
.\dist\x64\SysRecover.exe backup --dest D:\ea-lab\inc-test\b.esd --source D:\ea-lab\inc-test\src `
    --compress recovery --no-snapshot --append --yes
```
