> 状态：**调查中**（2026-10-03 建档）｜关联：PIT-108（结构复刻排除）、PIT-099/101/103/104/105/106/107

## 1. 现象（客户口述 + 证据）

- 用九转还原走 **Linux 重启还原**（目标是运行中的系统盘 C:）后，进入 Windows 桌面**一直转圈**、
  什么都打不开；**在任务管理器里重启 explorer 可临时恢复**，但**每次开机复发**。
- 没有报错弹窗；没有发现资源占满（客户观察）；桌面壁纸是"Win10 + 仿 XP"（C 盘根自定义壁纸）。
- PE 里就地还原（较早的一次）客户反馈正常。
- 开机时能看到 **"八戒一键还原"** 界面（易数一键还原的换皮版；客户系统里装了它 + 火绒 HipsDaemon + 酷呆桌面 Coodesker）。

## 3. 关键证据

1. **旧版那次（08:23）不可用**：`故障用户的资料\ZJRESTORE\logs\zjrestore-debug.log` 是旧版运行——
   无 `log mirror` 行（0.6.8 才加）、日志在 `found image` 后截断（PIT-099 旧 bug）、目标误判成 `/dev/sda1`。
   **不是 0.6.13 的那次**，不能作为新版问题的证据。
2. **新版那次跑对了**（客户照片/录像 + 100% 截图）：`mkntfs /dev/sda3 (start_lba=2129960)`、
   `hidden sectors = 2129960 (OK)`、`mode=block`、`21 GiB of 21 GiB (100%) done`、`log mirror: on`。
   → 还原管线执行完整、目标正确、块模式正常。
3. **卡死现场**：
   - 任务管理器：**两个 explorer.exe**（976 卡住 / 1756 是重启后的），另有 GuardEassosRestore、HipsDaemon、Coodesker。
   - 等待链：**explorer.exe(PID 976) 线程 1440 ⇄ 线程 5248**（同进程内线程互等）→ 桌面起不来；
     重启 explorer 换新 PID 后正常，下次开机复发。
   - `Ignoring extended attributes of 788 files`（Linux 侧丢 EA；PE/Windows 侧不丢）——两条路径的已知客观差异。
4. **Windows 侧暂存日志缺失**：客户从单文件（%TEMP%）运行，暂存日志随 C: 格式化消失；
   `G:\九转还原\6.13\logs` 里只有开窗/切模式记录（没有暂存），说明他实际没用该文件夹。
   新版那次的**救援层日志**应在 `D:\ZJRESTORE\logs\zjrestore-debug.log`（软件在目标盘时 software_dir 回退数据盘），
   客户送来的是早晨旧版那份——**待重取**。

### 8.1 新实锤：Linux 还原丢 EA（PIT-120）

- 客户 0.6.33 的 `zjrestore-apply.out` 唯一警告：`[WARNING] Ignoring extended attributes of 804 files`。
- 该字符串**只在 Linux 侧 wimlib**；Windows 的 `libwim-15.dll` 里没有 → **暂存重启（Linux）丢 EA；PE 就地（Windows）保 EA**。
- 实验室复现（`tools/ea-scan.cpp`：`--set` 造 EA）：造 `ea1.bin`（EA `ZJTEST=1`）→ 我们 `backup` + `extract`（Windows）→ `fsutil file queryea` EA 仍在 ✓。
- 这正是"别的软件（Windows 侧）没事、我们（Linux 侧）有事"的保真度差异——**右键卡死因果待交叉验证**。
- 取证：新增 `SysRecover.exe scan-ea`（列路径 + EA 名）；客户在 **PE 就地还原后**跑一次，把名单发回。
- **BCD**：`bcdboot` 重建会删第三方条目（客户备份里实证 `Boot Windows created by 石头`、`Windows_PE`）；0.6.35 起"BCD 有效即跳过 bcdboot"，重建前必导出 `bcd-backup-before-bcdboot`。
- **对照信息（用户 2026-10-05）**：客户自己试过**多款还原软件（易数一键还原等）均正常，只有我们的软件有问题** → 排除"源系统本身坏了"，把范围钉死在**我们的 Linux 还原管线**。
- **自动取证（0.6.37）**：备份收尾**自动**扫描源里的 EA 文件并落 `<logs>\ea-scan-<时间>.txt`（实测 30 万文件 15 秒、零用户操作）；发现 EA 时日志 WARN 并注明"Linux 救援还原会丢、PE 不丢"。
- **GUI 小 bug（0.6.37）**：「删除菜单」后按钮不回「安装菜单」——绑定副契约 `restore-task.conf` 未删；已修（`DeleteMenuBinding`）。
- **下一步交叉验证**：让客户用 **0.6.37 在 PE 就地还原 `20261005Win10.19044备份.wim`**（Windows 侧 apply 保 EA；BCD 不再重建）→ ①右键是否恢复（定因果）②`scan-ea` 名单发回（看那 804 个是什么）。
