# 16 - 客户故障调查：Linux 还原后桌面卡死（幽灵卡死）

> 状态：**调查中**（2026-10-03 建档）｜关联：PIT-108（结构复刻排除）、PIT-099/101/103/104/105/106/107
> 材料：`D:\Prog\_Project\SysRecover\故障用户的资料\`（客户发回的图/视频/日志，已重命名为可读文件名）

## 1. 现象（客户口述 + 证据）

- 用九转还原走 **Linux 重启还原**（目标是运行中的系统盘 C:）后，进入 Windows 桌面**一直转圈**、
  什么都打不开；**在任务管理器里重启 explorer 可临时恢复**，但**每次开机复发**。
- 没有报错弹窗；没有发现资源占满（客户观察）；桌面壁纸是"Win10 + 仿 XP"（C 盘根自定义壁纸）。
- PE 里就地还原（较早的一次）客户反馈正常。
- 开机时能看到 **"八戒一键还原"** 界面（易数一键还原的换皮版；客户系统里装了它 + 火绒 HipsDaemon + 酷呆桌面 Coodesker）。

## 3. 关键证据

1. **旧版那次（08:23）不可用**：`故障用户的资料\ZJRESTORE\logs\zjrestore-debug.log` 是旧版运行——
   无 `log mirror` 行（0.6.8 才加）、日志在 `found image` 后截断（PIT-099 旧 bug）、目标误判成 `/dev/sda1`。
   **不是 0.6.13 的那次**，不能作为新版问题的证据。
2. **新版那次跑对了**（客户照片/录像 + 100% 截图）：`mkntfs /dev/sda3 (start_lba=2129960)`、
   `hidden sectors = 2129960 (OK)`、`mode=block`、`21 GiB of 21 GiB (100%) done`、`log mirror: on`。
   → 还原管线执行完整、目标正确、块模式正常。
3. **卡死现场**：
   - 任务管理器：**两个 explorer.exe**（976 卡住 / 1756 是重启后的），另有 GuardEassosRestore、HipsDaemon、Coodesker。
   - 等待链：**explorer.exe(PID 976) 线程 1440 ⇄ 线程 5248**（同进程内线程互等）→ 桌面起不来；
     重启 explorer 换新 PID 后正常，下次开机复发。
   - `Ignoring extended attributes of 788 files`（Linux 侧丢 EA；PE/Windows 侧不丢）——两条路径的已知客观差异。
4. **Windows 侧暂存日志缺失**：客户从单文件（%TEMP%）运行，暂存日志随 C: 格式化消失；
   `G:\九转还原\6.13\logs` 里只有开窗/切模式记录（没有暂存），说明他实际没用该文件夹。
   新版那次的**救援层日志**应在 `D:\ZJRESTORE\logs\zjrestore-debug.log`（软件在目标盘时 software_dir 回退数据盘），
   客户送来的是早晨旧版那份——**待重取**。

## 4. 已排除项（本轮调查完成）

| 假设 | 结论 | 依据 |
|---|---|---|
| 分区结构非常规（ESP@LBA40、C: 非 1MiB 对齐、C: 顶到备份 GPT）导致 | **排除** | PIT-108：按客户结构精确复刻（`tools/vmtest/mk-customer-layout.py`）→ 完整还原 drill **6/6 PASS**（mkntfs start_lba=2129960 / hidden sectors OK / block apply / ESP 子镜像 / RESTORE DONE） |
| 易数 + 火绒 在该结构上的组合导致 | **排除**（至少未复现） | 用户按同结构装 Windows + 易数 + 火绒 → 测试完全正常 |
| 镜像本身损坏（备份时埋雷） | **基本排除** | 同镜像 PE 就地还原正常（客户口述，待用新版复验） |
| 还原目标选错/格式化错盘 | **排除** | 新版照片/截图：目标 sda3、offset 与契约完全一致 |

## 5. 当前假设（按概率）

1. **驻留驱动/外壳扩展"首启动竞态"**（火绒/酷呆/八戒服务 vs explorer 初始化）——
   吻合"等待链进程内互等、重启 explorer 就好、开机复发、无资源占满、无报错"。
   上轮 VM 复现未成功（组合/版本/时序可能不同）。
2. **我们 Linux 应用路径的元数据差异**（EA 丢失 788 文件；ACL 边界）——
   与"只有 Linux 还原出问题"的差异吻合；但目前无直接证据。
3. 硬件/盘（SMART 读不到结论，`st=unk`；重启 explorer 即好不太像）——低概率。
4. 其它：Windows Search/Defender 首启动扫描（不会"重启 explorer 立刻好"）——低。
