## 1. 这是什么

**SysRecover（知鉴一键还原 · 单机版）** —— 面向**电脑维修 / 系统维护 / IT 管理员**的
Windows 系统备份与一键还原工具：

- **备份**：把系统分区热备（VSS）成 WIM/ESD；
- **还原**：选镜像 + 目标分区，之后**自动二选一**：
  - **就地还原**（目标分区没被占用：在 PE 里、或还原到非系统盘）→ 格式化 + 应用 + `bcdboot`，**不重启**；
  - **重启还原**（还原正在运行的系统盘）→ 暂存任务 → 重启进**内置 Linux 救援层**执行 →
    自动重启回新系统。

**技术形态**：原生 C++、**零运行时依赖**（仅 `libwim-15.dll` 动态、随包）、CLI 优先 +
同源 GUI（双 exe）、`dist/` 约 54MB。

> ⚠️ 与早期规划 `WooMonlee/OnekeyRestore`（C# + 原生 VHD 引导 + VHDX 差分链、多点秒还原、
> 面向学校机房）是**两个产品**：顶层分层思想同源，但"还原机制"根本不同，文档与代码不混用。

## 2. 现在到哪一步了（都已实测）

| 场景 | 状态 |
|---|---|
| BIOS / MBR 全链还原 | ✅ |
| UEFI / GPT（Secure Boot 关闭）全链还原 | ✅ |
| UEFI / GPT + **Secure Boot 开启**全链还原 | ✅ **零注册、零交互** |
| 热备份(VSS) → 还原后正常进系统 | ✅（含注册表 hive 修复） |

| Windows 7 运行 | ⚠️ 需 UCRT（约 1.5MB 随包可解） |
| 服务器 RAID（`vmd`/`megaraid`/老 `mpt*`） | ⚠️ 待补驱动子集 |

## 3. 架构一句话

**Windows 侧（C++）负责备份、暂存任务、装引导、就地还原；Linux 侧只负责"把镜像写进分区"。
两侧不共享代码，只通过契约文件通信**（`restore-task.conf/json`、目标分区根的 `_zjresy*.log`）。
详见 `docs/02`（模块划分）与 `docs/04`（跨层契约）。

## 5. 代码入口（想改哪里看哪里）

| 想做的事 | 看这里 |
|---|---|
| 备份/还原流程编排、就地还原判定 | `src/app/ops.cpp` |
| 安全门禁（四检查、四元素校验） | `src/app/safety.cpp` |
| 引导（BIOS/UEFI/Secure Boot 三种链） | `src/boot/{grub,bcd,uefi}.cpp` |
| 镜像引擎（capture/apply/verify/probe） | `src/wim/wim.cpp` |
| 磁盘枚举 | `src/disk/disk.cpp` |
| GUI | `src/gui/main_form.cpp` + `ui_skin.cpp`（自绘控件） |
| 救援层实际执行还原 | `bootfiles/zjrestore-lite.sh` + `bootfiles/alpine/init` |
| 救援层组装（内核/模块来源） | `tools/build-debian-rescue.py`（当前；`tools/build-ubuntu-rescue.py` 为历史） |

## 6. 怎么构建与自测

```bash
mingw32-make -f Makefile all        # CLI + GUI（工具链路径写死在 Makefile 头部）
mingw32-make -f Makefile package    # 部署到 dist/
powershell -File tools/vmtest/uefi-ubuntu-smoke.ps1   # QEMU 回归：救援层能起来
```

## 8. 讨论与协作约定

- **改契约字段**（`restore-task.*` / `progress.json` / `_zjresy*.log`）→ **双端同步发版**（红线）。
- **改代码前**先读 `AGENTS.md` §0「开工前必查 5 条」+ §13 坑位册对应条目。
- **新踩的坑**按 PIT 模板登记进 `AGENTS.md` §13（编号递增），别只留在聊天里。
- **提交前**：`make all` 必须 **零警告**（第三方 Duilib 的历史警告除外），并跑相关 QEMU 回归。
