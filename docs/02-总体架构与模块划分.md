# SysRecover · 总体架构与模块划分

> 文档版本：v1.0（2026-09-20）｜关联：《01-需求与定位》《03-引导设计》《04-跨层契约》
> 目标：把大功能拆成低耦合模块，改一处不牵连全盘；Windows 侧与 Linux 侧只认契约。

---

## 1. 分层与依赖方向

```
┌──────────────────────────────────────────────────────────────┐
│ cli / gui     SysRecover.exe（console）/ SysRecoverUI.exe（windows）
│               双 exe 共享同一套 app 层；GUI 只调 app，不直连 wim/boot
├──────────────────────────────────────────────────────────────┤
│ app           编排：RunBackup / StageRestore（含就地还原）/ safety / shortcut
├──────────────────────────┬───────────────────────────────────┤
│ wim                      │ boot                              │
│  WimEngine(libwim RAII)  │  bcd / grub / uefi / task / bootfix│
├──────────────────────────┴───────────────────────────────────┤
│ disk            DiskEnumerator / VolumeMapper / PartitionStyle │
├──────────────────────────────────────────────────────────────┤
│ common          Result<T> / Logger / Progress / RunProcess(CreateProcessW)
│                 / SingleInstance / PathUtf16 / IniConf
└──────────────────────────────────────────────────────────────┘
                 依赖只向下；common 不依赖任何人
```

## 2. 模块清单（`src/`）

| 模块 | 目录 | 职责 | 依赖 |
|---|---|---|---|
| common | `src/common/` | 进程执行、日志、进度、单实例、路径 | 无 |
| disk | `src/disk/` | 磁盘/分区枚举（`DeviceIoControl`，**禁 WMI**）、固件类型判 | common |
| wim | `src/wim/` | `libwim` 封装（capture/append/apply/verify/probe）、排除清单 | common |
| boot | `src/boot/` | BCD、GRUB4DOS 部署、**UEFI 固件启动项**、任务与日志写入、bootfix | disk+common |
| app | `src/app/` | 备份/还原编排、就地还原判定、安全门禁、快捷方式 | disk+wim+boot |
| cli | `src/cli/` | `SysRecover.exe`：list/backup/restore/verify/images/diag/version | app |
| gui | `src/gui/` | `SysRecoverUI.exe`：经典 Duilib 窗口 + 工作线程 | app |

## 3. 三条禁令（架构层）

1. **禁 WMI 读盘**（PE 不可用）—— 只用 `disk` 的白名单 API。
2. **禁抄 `wimlib-imagex` 源码**（GPLv3）—— 只经 `wim` 模块调 `libwim`。
3. **禁 GUI 直调 `wim`** —— 必须经 `app` 编排（保证 CLI/GUI 行为一致）。

## 4. 两份运行环境、一个契约

| 侧 | 语言/形态 | 职责 |
|---|---|---|
| Windows 侧 | C++（`cli`/`gui`/`app`/`wim`/`disk`/`boot`） | 备份、暂存任务、写契约、装引导、就地还原 |
| Linux 侧 | `bootfiles/{alpine/init, zjrestore-lite.sh}` + 内核/模块 | 真正执行"格式化 + apply + 修引导 + 重启" |

两侧不共享代码、不互相链接，**只通过契约文件通信**（见《04-跨层契约》）。


## 6. 变更隔离原则

1. 上层只调下层接口；`common` 无依赖，改动不牵连上层。
2. 引导方式按"环境"分支（BIOS / UEFI 关 SB / UEFI 开 SB），互不影响，一处出问题可单独回退。
3. 救援层与 Windows 侧**只认契约**，可独立升级（但要双端同步发版，见 §5 红线）。
4. 纯逻辑（安全校验、命名规则）与副作用分离，便于单测/复用。
