## 0. TL;DR（30 秒）

- **同族异机（换主板/换机器，AHCI/NVMe/IDE 之间）今天已基本可用** —— 实验室实测：还原后的
  Win10 系统盘把控制器从 NVMe 换成 IDE，**直接启动到桌面**（我们现有的"按目标盘风格重建引导"
  已经覆盖一半）。
- **真正的硬骨头 = 引导期缺存储驱动**（实验：换成 virtio 后进不去系统，0x7B 蓝屏形态）：
  源机用了非收件箱驱动（Intel RST/VMD、RAID 卡等）时，目标机没有对应驱动 → 起不来。
- **推荐先做 T1「轻量异机」**：Linux 救援层用 `hivexsh` 离线改 SYSTEM 注册表（存储驱动
  boot-start 白名单 + 清 MountedDevices）。**体积 +0.3~0.4MB、速度零影响、风险低**（默认关）。
- **T2「驱动注入」只建议做 Windows/PE 侧**（用户提供驱动文件夹 + DISM），**不内置驱动包**
  （+50~300MB、授权/维护问题）。**T3（sysprep generalize 级完整通用）不做。**

## 1. 场景定义

"异机还原" = **A 机的备份镜像，还原到 B 机**（不同主板/芯片组/存储控制器），还原后系统要能
正常启动并基本可用。区别于我们当前的默认场景（同机还原：修同一台机器的系统盘）。

用户群体里这是真实需求：维修人员"客户机系统盘坏了/换新机，用旧备份顶上去"。

实验素材：`D:\EA-lab\win10test\win10test.vhd`（真实 Win10 21H2 测试 VM 的系统盘，已用 0.6.38+

| 实验 | 方法 | 结果 | 结论 |
|---|---|---|---|
| **NVMe → IDE** | 同一 VHD 改挂 `-drive if=ide`，OVMF 启动 | ✅ **直接到桌面**（截图 `D:\EA-lab\win10test\shot-ide.png`） | 同族控制器切换，Win10/11 **收件箱驱动**（pciide/storahci/stornvme）已覆盖；我们现有的引导链（bcdboot 按目标盘重建）本身适配 |

| **MBR/BIOS 源（无 ESP）→ GPT/UEFI 目标**（跨固件） | 把上一台"BIOS 系统"再备份 → 救援还原到 GPT 盘 → `bcdboot /f UEFI` 补 ESP → OVMF 启动 | ✅ **启动到桌面**（`shot-uefi3/4.png`） | **BIOS→UEFI 方向已验证**（PIT-127） |

## 3. 异机还原的四个问题域

### 3.1 引导期存储驱动（核心）
- Windows 启动内核阶段必须能挂载系统卷。源机若用了**非收件箱**驱动（Intel RST/VMD
  `iaStorAC`/`iaStorVD`、RAID 卡驱动、老式厂商驱动），目标机没有 → 0x7B。
- 需要两件事：
  1. **把常见收件箱控制器驱动强制为 boot-start**（`Start=0`）：`msahci`/`storahci`/`stornvme`/
     `iaStorV`/`iaStorAVC`/`amdsata`/`amdxata`/`pciide`/`atapi`/`vmbus`/`storvsc` 等。
     （Win10/11 默认多数已是 boot-start，但**"优化工具"会禁掉**（Start=4），换机就炸。）
  2. **真缺的驱动**（VMD/RAID/virtio）**只能注入厂商驱动** → 见 T2。
- 注：`iaStorVD`（VMD）的收件箱支持因 Windows 版本而异（新 Win10/11 大多带），老系统/RAID
  模式仍可能要厂商驱动。

### 3.2 盘符映射
- `HKLM\SYSTEM\MountedDevices` 记录了"盘符 ↔ 卷"绑定。换机器/换盘序后可能让**系统盘拿不到
  C:**（后果：用户目录、快捷方式、软件全乱）。标准做法：**清空 MountedDevices**，让 Windows
  重新分配（系统盘通常拿回 C:）。同行工具（傲梅/Acronis）都做这一步。

### 3.3 固件 / 分区风格（UEFI↔BIOS、GPT↔MBR）
- **我们已经覆盖，且 2026-10-06 已实验室实测双向通过**（见 §2 及 PIT-127）：
  - **GPT/UEFI 源（含 ESP 子镜像）→ MBR/BIOS 目标**：ESP 子镜像正确跳过（无 ESP 机器）→ bootfix（BIOS 味道）+ PBR 引导区 → **SeaBIOS 启动到桌面 ✓**；
  - **MBR/BIOS 源（无 ESP）→ GPT/UEFI 目标**：ESP 不动、跳过 PBR → 暂存侧 `bcdboot /f UEFI` 补 ESP（BCD 有效即跳过）→ **OVMF 启动到桌面 ✓**。
- 机制：`UseUefiBootFor()` 按**目标盘分区风格**选引导链（PIT-092）；Windows 侧不区分固件（同一份系统文件），BCD 由 `bcdboot`/bootfix 按目标风格重建。
- 边界：UEFI 目标 ESP 的 BCD 若指向**别的分区**（多系统场景）→ 跳过逻辑不比较目标分区，可能启动旧系统（边缘场景，见 PIT-127）。

### 3.4 非技术坑（必须在文档/UI 里向用户说明）
- **Windows 激活**：硬件变了数字许可证可能失效（OEM 版尤其），需要重新激活——非技术问题，
  但要提前告知用户，别让用户以为是还原失败。
- **其他设备驱动**（网卡/显卡/声卡）：**不影响开机**，首启 PnP 自动装收件箱驱动；缺的进系统后
  由用户补装。首启会因 PnP 重装设备**慢几分钟**（异机固有，非我们的开销）。

## 4. 同行做法（参照）

| 工具 | 异机还原 | 做法 |
|---|---|---|
| 傲梅轻松备份（AOMEI） | ✅「异机还原」（**付费版功能**） | 注册表适配 + **驱动库**（内置/用户提供） |
| Acronis True Image | ✅「Universal Restore」（**附加组件**） | 驱动包注入 + 硬件抽象清理 |
| Macrium Reflect | ✅「Redeploy」（**企业版**） | 驱动注入 + 引导修复 |
| 易数一键还原 | ❌ 无 | — |

> 结论：**异机还原是"高级/付费"功能，且核心资产是驱动包**。我们不做驱动包（体积/授权/维护），
> 走"收件箱驱动 + 注册表适配（T1）+ 用户自备驱动（T2）"路线。

## 5. 方案分级（建议实施顺序）

### T1「轻量异机」—— 推荐先做（Linux 救援层，离线注册表适配）

**做什么**（主 apply 完成后、目标分区还挂着时执行——与 bootfix/EA 投放同款阶段）：
1. 用 `hivexsh` 打开 `<目标>\Windows\System32\config\SYSTEM`：
   - 把 §3.1 的**存储驱动白名单**逐个设 `Start=0`（不存在就跳过；不新建键）；
   - 清 `HKLM\SYSTEM\MountedDevices` 的键值（保留键本身）；
2. **hive 日志处理（⚠️ 关键细节）**：hivex 只读写主文件、不重放 `.LOG1/.LOG2`；编辑后日志与
   主文件序列失配 → 必须处理（方案：编辑成功后删除该 hive 的 `.LOG1/.LOG2`；**必须与
   PIT-056 的"脏 hive 需要日志恢复"组合回归**：VSS 热备前已 RegFlush、多数 hive 是干净的，
   但 `--no-snapshot` 冷备可能脏 → 测试矩阵里要有这一项）；
3. 写回后**复核**（重新打开能读出刚写的值）；失败只记日志**不阻断主流程**（EA 投放同款语义）。

**体积**（已实测，2026-10-06）：
- Alpine v3.20 `hivex` 1.3.23-r3：包 38.7KB；`hivexsh` 只依赖 `libhivex.so.0` + `libreadline.so.8`
  + musl；`libhivex.so.0` 只依赖 musl —— **不需要 libxml2、不需要 perl**（那是 `hivexregedit`
  才要的，我们不用）。
- 合计新增（压缩后）：hivex 38.7KB + readline 120KB + ncursesw ≈ **+0.3~0.4MB** →
  initramfs 15.2 → ~15.6MB。

**速度**：救援层 +秒级（hive 打开/编辑/写回）；**备份与 apply 零影响**；目标首启 PnP 变慢是
异机固有（见 §3.4）。

**安全设计**（红线）：
- 异机模式**默认关闭**，UI 勾选才做（CLI `--universal`）；普通还原路径**一行不碰**；
- 改前把 SYSTEM hive 复制为 `SYSTEM.zjbak`（同目录，Windows 侧可回滚）；
- 只动 SYSTEM hive、只动白名单值与 MountedDevices；不做 Enum/服务删除等激进清理；
- 全程 fail-safe：任何一步失败 → 日志 + 跳过，主还原不受影响。

**集成点**：`zjrestore-lite.sh` 主 apply 后（bootfix 之前/之后均可）；构建侧
`tools/build-debian-rescue.py` 增加 hivex/readline/ncursesw 包；initramfs 依赖由构建脚本自解。

### T2「驱动注入」—— 只做 Windows/PE 侧（后做）

- 仅**就地还原（PE / 非系统盘）路径**支持：用户提供驱动文件夹 → 系统自带
  `dism /image:<目标>:\ /Add-Driver /Driver:<folder> /Recurse /ForceUnsigned`（DISM 会处理
  INF/DriverStore/注册表，这是唯一可靠的注入通道）。
- **Linux 救援侧不做注入**（等于重造 DISM，工作量与风险不成比例）。
- **不内置驱动包**：+50~300MB 体积、厂商驱动再分发授权不明、维护成本高。
- 工作量 ~3-5 天（含 PE 实测）。

### T3「完整通用」—— 不做

- sysprep generalize 级（离线设置 OOBE/重置 SID/清 Enum）——改系统状态、风险大，
  与 T1+T2 收益重叠，且会破坏"还原=原样恢复"的产品语义。

## 6. 测试计划（做 T1 时按此执行）

**QEMU 控制器矩阵**（素材：win10test.vhd + 我们的还原链）：
| 用例 | 期望 |
|---|---|
| NVMe → IDE / IDE → NVMe / NVMe → AHCI | ✅ 本来就过（回归基线，见 §2） |
| 镜像里把 `storahci` 的 `Start` 改成 4 → 还原到 AHCI 目标 | **不修复必蓝屏 0x7B；T1 修复后能起**（验证 T1 有效性） |
| 镜像里把 `stornvme` Start 改成 4 → 还原到 NVMe 目标 | 同上 |
| virtio 目标（缺驱动） | 仍失败（预期）→ 归 T2/文档说明 |
| 多分区机器改盘序（MountedDevices 场景） | 系统盘仍拿 C: |
| **脏 hive（--no-snapshot 冷备）+ 异机模式** | 日志删除策略不破坏启动（PIT-056 组合回归） |
| **普通还原（异机模式关）** | 与现状完全一致（一行不碰） |

**真机验证**：至少一台"不同芯片组"的真机（如 AMD 板 → Intel 板）走一次完整链（用户可协助）。
