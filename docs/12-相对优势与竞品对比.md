## 1. 先分清楚：同行是几类东西（定位不同，别硬比）

| 类别 | 代表 | 本质 | 我们的关系 |
|---|---|---|---|
| **A. 外部 PE / U 盘救援类** | 微PE、WinPE 装机盘、各类 PE 工具箱 | 靠**外部启动介质**进 PE 手工操作 | 我们**不需要 U 盘/PE**（救援层内置在软件里）|
| **B. 系统内一键还原类** | **SysRecover**、易数一键还原、傲梅一键还原、联想 OKR | 装在系统里，一键把系统回滚 | **正面同类**，本文件主要比这类 |
| **C. 系统工具箱类** | Dism++ | 系统优化/清理 + WIM 备份，**不是一键还原流程** | 功能有交集（都能备份 WIM），路线不同 |
| **D. 专业磁盘映像套件（国际商业）** | **Image for Windows**（TeraByte）、Acronis、Macrium | Windows 主程序 + **自建/可选的预启动恢复环境** | **架构同族、定位不同**（见 §2.5）|

> 一句话定位：**我们是 B 类，且刻意把"A 类的硬件覆盖"塞进了 B 类的体验里。**
> 和 D 类的区别：**它把选择权交给用户，我们把选择替用户做完**（§2.5）。

## 2.5 Image for Windows 4.13（TeraByte，国际商业套件）—— 重点对比

**它是什么**（据官网/用户手册，2026-09 调研）：TeraByte Drive Image Backup and Restore Suite，
含 **Image for Windows**（主程序）+ Image for DOS + Image for Linux + **Image for UEFI（IFU）** +
OSD 工具 + **TBWinPE/TBWinRE** 构建器 + TBIView/TBIMount/TBIHD + PHYLock。约 **$38–59/授权**（企业部署另计），
安装包约 **198 MB**，**32/64 位都有**，25 年老牌。

**和我们的架构关系（关键）**：IFW **主程序本身不带独立 UEFI 启动模块**，还原系统盘时要**重启进外部环境**
（IFU 裸 UEFI 程序 / IFL / IFD / TBWinRE）。**这正是我们的架构**（Windows 侧暂存 → 重启进内置 Linux 救援层）；
它的"重启进 TBWinRE 的 WIM"≈ 我们的"暂存 + 单次启动项"。**区别在于：它给用户一整套环境让用户自己挑/自己造介质，我们把这一套内置并自动部署。**

| 维度 | **SysRecover** | Image for Windows 4.13 |
|---|---|---|
| 定位 | 系统内**一键还原**（维修/非专家）| 专业磁盘映像套件（IT/发烧友）|
| 恢复环境 | **内置一套，安装时自动部署，零设置** | 多套可选（DOS/Linux/**IFU**/WinRE/WinPE），**但用户要自己造启动盘** |
| 自动化 | **一键 + 静默模式 + `progress.json`**（机房批量）| CLI/脚本/Simple 模式，流程更"专业向" |
| 镜像格式 | **WIM/ESD（微软标准，可挂载/互操作）** | 私有 **`.tbi`**（厂商锁定）|
| 增量/差分/链合并 | **无** | **有**（成熟）|
| 加密 / 文件级提取 / 分区管理 | **无** | **有**（AES-256 / TBIView / BootIt）|
| 硬件覆盖 | Debian 内核 **494 个存储/fs 模块**（RAID 全覆盖，已 QEMU 实测）| **WinPE/WinRE 可注入厂商驱动**（覆盖面可能更广）|
| Secure Boot | **Debian 双签 shim（CA2011+CA2023）**，零注册零交互 | **微软 2023 CA 签名**（自费送签），零交互 |
| 还原后能开机 | **自动**修 NTFS 引导区 + 补 `\Boot\BCD`（便携 BCD，跨盘/跨机器）| 有 `fixboot`/BCD 修复（同样成熟）|
| 体积 | 发布包 **39 MB** | 安装包 **198 MB** + 介质更大 |
| 许可/成本 | 自研，无按席位授权（许可合规干净）| **商业付费** |
| 32 位 | 计划中（`0.3`）| **已有** |

**结论**：它强在**功能深度 + 环境可选性 + 成熟度 + 现成的 32 位/微软 2023 CA 签名**；
我们强在**零设置一键体验 + 标准 WIM 格式（不锁定）+ 体积 1/5 + 无席位成本 + 机房可编程性**。
**一句话：它是给专业人的工具箱，我们是给维修/运维的一键流程。**

## 3. 我们的实质优势

### 3.1 硬件 —— 把"PE 类工具的硬件覆盖"搬进了一键还原
- 救援层是 **Debian 签名内核 + 494 个存储/文件系统模块**（2026-09-24 裁剪后，原 779 个）：
  `nvme`/`ahci`/`usb-storage` 不用说，**`megaraid_sas`/`mpt3sas`/`isci`/`vmd`/`hpsa`/`aacraid`/`arcmsr`/
  `pm80xx`/`mvsas`/`lpfc`/`qla2xxx`/`virtio_scsi`** 都在里面
  （QEMU 实测加载成功、认盘正常、**端到端还原演练通过**）。
- 实务意义：**服务器/阵列卡机器上，很多 PE 工具认不到硬盘**；我们在这里能干活。
- 而且**不需要外置 U 盘 / PE 盘**：软件自己就把救援层部署好，用户一键走完。

### 3.2 还原后的"能开机" —— 我们替用户做完了
同类工具最常见的翻车点是"还原成功、但开不了机"。我们做了三件事：
1. 写回**完整的微软 NTFS 引导区**（扇区 0 的 426 字节 **+ 扇区 1..8**，这是当年黑屏光标闪的根因）；
2. 补上万能镜像普遍缺失的 `\bootmgr` + `C:\Boot\BCD`（在 Windows 侧导出**可移植 BCD**，Linux 侧写入）；
3. BCD 用 `device boot`（**与盘符、磁盘号无关**）→ **换机器、换盘符都能起**。
   实测：**Win7 宿主还原 Win10 镜像，正常启动**（宿主与镜像系统版本可以不同）。

### 3.3 Secure Boot —— 不用让用户去 BIOS 里关
- 链路：`固件 → shimx64.efi（**微软双签 CA2011+CA2023**）→ grubx64.efi（**Debian 签名**的 GRUB）→ Debian 签名内核 + 我们的 initramfs`。
- **没有任何绕过**：链上每个可执行文件都有合法签名，和 Debian 正常开机同一条路；用户**零注册、零交互**。
- 2026-09-23 由 Ubuntu 链换成 **Debian 链**：shim 是 **CA2011 + CA2023 双签** → 覆盖"**2026 新出厂、只信 CA2023**
  的固件"（Ubuntu 目前只有 CA2011 单签，做不到）。机制不变，只是链上的内核/GRUB 换成 Debian 的。
  诚实边界：**用户 VMware（Secure Boot 开）实测还原成功** ✓，但"只信 CA2023 的新固件"仍**待真机验证**。

### 3.4 运维友好（面向 IT 管理员 / 机房）
- **CLI 优先**：`backup / restore / list / images / verify / diag / shortcut` 全命令化；
  带 `requireAdministrator` 清单，在管理员命令行/计划任务最高权限/PsExec `-s`/SCCM 下**全程不弹 UAC**。
- **静默模式**：勾上后**没有任何对话框**，直接暂存 → 自动重启 → 全自动还原 → 回到新系统。
- **退出码规整**：`0` 成功 / `1` 通用失败 / `2` 参数错 / `3` 需管理员 / `4` 危险目标被拒 / `5` 镜像校验失败 / `6` 取消。
- **进度与结果可被外部读**：`progress.json` + `_zjresy*.log`（含磁盘型号/序列号/偏移/大小），方便做批量面板或远程排查。

### 3.5 安全 —— fail-closed，手抖不了
- **四元素校验**（GUID / 磁盘序列号 / 偏移 / 大小）+ **还原四检查**（目标是 ESP / BitLocker / 恢复分区 /
  镜像文件就在目标分区内）→ 任一命中**直接拒绝**（退出码 4），不做"我以为你要"的猜测。
- **拒绝坏镜像**：镜像带"写入中"标志或完整性不过 → **直接拒绝**，不会 apply 到一半黑屏。
- **不碰磁盘 MBR**：只格式化目标分区；救援文件放目标分区，**数据盘根目录零新增** → 双系统/多盘更可控。
- **中断可控**（`0.1.4`）：任务执行中可点叉叉选「终止并退出」；产物是**原子写**（先写 `<目标>.tmp`、
  成功才改名）→ **中断不会毁掉已有的同名镜像**。

### 3.6 体积与交付
- Windows 侧仅 **3.92 MB**（CLI 1.31 + GUI 2.14 + `libwim-15.dll` 0.47）；发布包 **39 MB** 中
  **≈90% 是救援层**（内核 11.6 + initramfs 20.5）。2026-09-24 裁掉用不到的内核模块后，发布包从 54 MB 降到 39 MB。
- **零运行时依赖**（静态链接）；Win7 装个 VC++ 运行库即可，或把 UCRT DLL 随包带上（机制已就绪）。

### 3.7 商业与维护
- **许可干净**：`libwim` 仅**动态链接**（LGPL）、其余为**单独分发**的聚合、**未静态链接任何 GPL、未改第三方源码**
  → 不受 copyleft 衍生产品条款约束（自有代码已以 MIT 开源）。
- **代码与文档是自己的**：C++17 + 手写 Makefile + 钉版工具链；15 份文档 + **71 条坑位册**
  → 可交接、可迁移、可多人接手（`docs/11` 就是为此写的）。

3. **两项主路径仍待实测**：PE 就地还原、RAID 真机（`docs/11` §3 有清单）。

## 5. 话术版（对客户 / 合作方）

**30 秒版**
> 一键还原工具，备份系统成镜像、需要时一键回滚。和同类比，我们三件事做得更实在：
> ①**阵列卡/服务器机器也能看到硬盘**（内置 Linux 救援层，1000+ 存储驱动）；
> ②**还原完保证能开机**（引导区、BCD 全自动修好，跨机器/跨盘符都行）；
> ③**Secure Boot 不用关**（走微软签名链，零注册零交互）。另外有完整命令行和静默模式，适合批量部署。

**被问"你们比易数/傲梅好在哪"**
> 傲梅/联想 OKR 装机要求先关 Secure Boot，我们不用关；
> 易数在**新硬件（2026 出厂只信新证书的机器）**上比我们快一步，那块我们正在追（要么等 Ubuntu 更新签名，要么换签名链）；
> 易数背后是 DiskGenius，分区管理和多点还原比我们强，我们不做那些——**我们只把"系统备份+还原"这一件事做透**。

**被问"有没有多点还原/秒还原"**
> 没有。我们这条产品线只做单点系统还原；多点秒还原是**另一条产品线**（VHDX 差分链那套），两个产品分开推进。

**被问"安全吗，会不会抹错盘"**
> 四元素校验 + 还原四检查，命中 ESP/BitLocker/恢复分区或者镜像就在目标分区里，**直接拒绝**；
> 镜像带"没写完"标志也会被拒；只格式化目标分区，不动磁盘 MBR 和数据盘根目录。

**被问"和 Image for Windows / Acronis 比呢"**
> **架构同族**（Windows 主程序 + 独立预启动恢复环境，见 §2.5），但定位不同：他们是**专业工具箱** ——
> 功能更深（增量/差分/加密/分区/BootIt），但**要用户自己造启动盘**、镜像用**私有 `.tbi` 格式**、
> 约 **$38–59/席位**、安装包约 **200 MB**；我们是**一键流程** —— **零设置**（救援层安装时自动部署）、
> **标准 WIM/ESD 格式**（可挂载、不锁定）、发布包 **39 MB**、无席位成本。
> 一句话：**他们把选择权交给用户，我们把选择替用户做完。**
