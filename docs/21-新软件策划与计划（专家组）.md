# 21 - 新软件策划与计划（专家组，2026-10-09）

> 新软件沿用「九转还原 / SysRecover」品牌与本仓库继续演进（用户 2026-10-09 裁定）。
> 核心架构方向：**Windows 原生解压 + Linux 仅做目录改名交换**（A 引擎），彻底绕开
> Linux 侧 wimlib/ntfs-3g 的已知限制（EA/非微软 reparse/EFS 等）。
> 本文件按 PIT-085 多角色评审法组织：各角色独立意见 → 交叉收拢 → 架构决策 → 阶段计划。

## 1. 组织与角色意见（收拢）

| 角色 | 关注点 | 结论 |
|---|---|---|
| 架构/存储 | 数据写入放 Windows（原生保真）、Linux 只做元数据交换（rename 秒级） | **采纳**；唯一硬门槛 = 空间 ≈2×（预检，不满足回退） |
| Windows 内核/引导 | 交换后引导修复（BIOS PBR / UEFI ESP+bcdboot）不变；交换在救援层离线做 | 沿用现有引导链（BCD/GRUB4DOS/UEFI+Debian SB 链） |
| 安装部署/运维 | 现场无网、介质多样（U 盘/PE/光盘）；日志统一 | 沿用搬迁/日志/黑匣子（已归并）机制 |
| 测试 QA | 交换中断 = 半新半旧（与现 apply 中断同级风险）；需事务化+回滚设计 | P1 定义交换事务；P3 新增"中断演练" |
| 安全/合规 | 不引入新第三方；引导链与签名资产不变 | 维持 §14 SBOM |
| UX | 解压需在 Windows 内等待；删除旧树延后 | 阶段化进度提示；首启后台删 `~old` |
| 代码维护性 | 淘汰自定义包格式（eapack/reppack）与补写器 | 用标准 WIM 修复子镜像 + 原生提取 |
| 文档 | 封存线与新线并行清晰 | docs/20（封存）+ docs/21（新线）+ 坟场制度 |

## 2. 基线架构（供 P0/P1 论证定稿）

- **A 引擎（主路径）**：
  1. Windows 侧：空间预检 → wimlib 原生解压镜像到 `<目标盘>:\~new`（含 ESP 子镜像与修复子镜像的处理）→ 写暂存标记 → 重启；
  2. 救援层（Linux）：挂载目标盘 → **顶层目录改名交换**（旧→`~old`，`~new`→原位，十几次 rename）→ 引导修复（BIOS PBR / UEFI 走 bcdboot 或已存 ESP）→ 重启；
  3. 首启（Windows）：RunOnce 脚本删除 `~old`（后台/延迟）+ 悬空引用清理（refscan）+ 收尾日志。
- **B 引擎（回退）**：现有 Linux 块模式 apply —— 仅在空间不足或特殊场景使用；其已知限制配"镜像元数据预检"（非微软 reparse → fail-closed 提示走 PE 就地）。
- **保留**：引导链、安全检查、契约、日志/黑匣子（归并版）、refscan、诊断包、搬迁、i18n。
- **淘汰（→ graveyard）**：eapack/reppack/补写器/EA 清单（A 引擎原生提取取代）；`zjrestore-lite.sh` 的 apply 段（替换为交换引擎）。
- **新增**：交换引擎（事务化+回滚）、空间预检、延迟删除、镜像元数据预检（reparse/EFS 检出）。

## 3. 阶段计划

| 阶段 | 内容 | 验收 | 预估 |
|---|---|---|---|
| **P0 原型验证** | 实验室搭 A 引擎原型（现有素材）：同机同镜像测 `Windows 解压` + `Linux rename 交换` + `首启删除` 耗时/空间/失败面，对比 B 引擎 | 数据表：耗时/空间/失败模式；结论"是否采纳 A 为主路径" | 1–2 天 |
| **P1 设计定稿** | 交换事务（中断/回滚）、空间门槛与预检、兼容矩阵（BIOS/UEFI × MBR/GPT × 单/多盘）、修复子镜像格式 | ADR + 设计文档评审通过 | 2–3 天 |
| **P2 MVP** | A 引擎端到端（Windows 解压器 + 救援交换 + 首启清理 + 引导修复） | 实验室全链跑通（真启动） | 3–5 天 |
| **P3 回归** | 复用旧矩阵重建：drill/3disk/镜像批次/跨固件/SB + 新增交换中断演练 | 矩阵全绿（重做后的测试线） | 3–5 天 |
| **P4 试点** | 两个真实客户场景（家里电脑、三盘机） | 现场通过 + 支持包复核 | 按客户节奏 |

## 4. 风险清单（Top）

1. 空间 2× 门槛让 A 引擎不适用小盘机 → 保留 B 回退 + 预检透明化；
2. 交换中断的半新半旧 → P1 事务化（先 `~new` 完整、再原子改名、`~old` 可回滚）；
3. 首启删除失败残留 `~old` → 重试/登记下次开机删除（复用既有延迟删除经验，注意 PIT-123 同名删除坑）；
4. 解压期间的 Windows 环境变化（用户中断/断电）→ `~new` 半成品可重解（幂等）；
5. 旧镜像兼容 → 镜像元数据预检 + PE 就地路径。
