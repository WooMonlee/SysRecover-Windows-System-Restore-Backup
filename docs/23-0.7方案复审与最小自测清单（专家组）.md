# 23 - 0.7 方案复审与最小自测清单（专家组，2026-10-09）

> 三问：①现在方案（A 引擎 = Windows 原生解压 + Linux 仅改名交换）在逻辑上是否最优？
> ②有哪些值得优化的地方/该抛弃的代码？③新一轮最小自测清单。

## 1. 专家组复审：A 引擎是否最优

### 1.1 候选方案对照

| 方案 | 数据写入 | 保真 | 空间 | 合规 | 结论 |
|---|---|---|---|---|---|
| **A（现方案）** | Windows 原生（wimlib Windows 路径） | 全原生（reparse/EA/ACL/时间戳） | **2×** | ✅ 不碰 WinPE | **最优（在约束内）** |
| B（封存线） | Linux 块模式 apply | 丢 EA/非微软 reparse、EFS 跳过 | 1× | ✅ | 保留为**小空间回退** |
| C（全 PE 内 apply） | WinPE 里 Windows wimlib | 同 A | 1× | ❌ **违反 §2 红线**（禁 WinPE/WinRE） | 否决 |
| D（扇区级克隆） | 裸扇区 | 全保真 | 1× | — | 不做（非本产品形态/镜像格式不兼容） |

**逻辑结论**：在"**不得用 WinPE + 已有 Linux 救援层 + 要求原生保真**"三重约束下，A 是唯一同时满足的方案；
C 看似省空间（无需 2×）但踩红线；B 的保真缺陷正是新线要根除的。

### 1.2 A 方案的逻辑漏洞审计（须在 P1/P2 堵上）

| # | 漏洞 | 对策（必修） |
|---|---|---|
| L1 | `~new` 解压**中途中断**（断电/用户取消）→ 半棵树 | **完成标记 + 报错不继续（用户 2026-10-09 定案）**：解压成功后写 `~new\.zj-done`；失败/中断 → **报错、绝不碰旧树、删除 `~new`、让用户换镜像**；断电场景由**下次 Windows 启动检测孤儿 `~new`（无标记）→ 提示并清理**；首版不做断点续解 |
| L2 | 特殊顶层项（`$Recycle.Bin`/`System Volume Information`/pagefile 等）不能简单进 `~old` | 交换清单白名单化：特殊项**删除旧+移新**或**保留旧**（P1 定案；两者都不影响启动） |
| L3 | 交换自身中断 → 半新半旧 | P1 事务化：**先把 `~new` 全部就位准备、再原子改名**；旧树在 `~old` 可回滚（P0 先记录行为） |
| L4 | 目标盘**放不下 2×** | 回退链：①目标盘 2× 不够 → ②别的分区解压 + Linux **跨区拷贝**（慢但可行）→ ③B 引擎；空间预检（`EstimateSwapSpace`）负责判定并提示 |
| L5 | UEFI 的 ESP 不在主镜像里 | 复用现有 ESP 子镜像机制：Windows 侧把 ESP 子镜像 `extract --index N --dest <ESP挂载点>`（原生写入）✓ |
| L6 | 旧树删除失败（占用/权限） | 首启删失败→登记 `MOVEFILE_DELAY_UNTIL_REBOOT` 重试（PIT-123 同名坑注意）；日志留证 |

**总评：方案逻辑成立；L1/L2 是 P2 前必须有的安全件，L3 是 P1 设计件。**

## 2. 优化机会 + 该抛弃的代码（第二批坟场候选）

### 2.1 优化（A 引擎带来的简化）
| # | 项 | 收益 |
|---|---|---|
| O1 | **救援层不再需要 wimlib/apply**：交换只需 ntfs-3g 挂载 + rename → 裁掉 initramfs 的 `wimlib-imagex`/`libwim.so`/镜像扫描/apply 段 | initramfs 更小、脚本更简单（救援=交换+引导修复） |
| O2 | **EA/reppack 整链退役**：A 引擎原生提取 → `eapack/reppack/补写器/GPO 钩子` 全部不需要 | 删 ~千行 + 不再打子镜像 + 备份更快 |
| O3 | **refscan 投放简化**：补写器 exe → 主 exe 新增 `fix-refs` 命令（refscan 代码已在 `common/`），首启/GPO 直接调主 exe | 少一个二进制、逻辑单源 |
| O4 | **非微软 reparse 不再需要备份端排除**（A 引擎能装）→ `FindNonMsReparse/CaptureReparse/EnsureExclusionConfig(extraRel)` 退役；B 引擎回退时由"镜像元数据预检"拦（提示走 A） | 备份路径更干净 |
| O5 | 解压进度接线：`WimEngine::Apply` 已有 `ProgressFn` → GUI 进度条直接复用 | 大镜像解压可视 |

## 4. 复审决议（终版，2026-10-09，含用户裁定）

| # | 决议 |
|---|---|
| D1 | **A 引擎为主路径**（Windows 原生解压 + Linux 改名交换），B 保留为小空间回退 |
| D2 | **L1 定案（用户）**：解压失败/中断 → 报错、不碰旧树、删 `~new`、让用户换镜像；断电由下次启动清孤儿 `~new`；首版不做断点续解 |
| D3 | **L2 定案**：`$Recycle.Bin`/`System Volume Information`/pagefile/swapfile/hiberfil → 交换时**删旧**（新树自带或首启重建），不进 `~old` |
| D4 | 首版**非事务**交换（P0 记录中断行为）；事务化/回滚 = P1 |
| D5 | **执行序**：① 交换脚本 `bootfiles/zjswap.sh`（✅ 已写，含标记校验/fail-closed/特殊项处理）→ ② Windows 侧 `StageRestoreSwap`（空间预检→`extract --all` 到 `~new`→写 `.zj-done`→契约 `engine=swap`→引导层→重启）→ ③ 首启删 `~old` + refscan → ④ T1–T7 |
| D6 | 优化排期：O5（解压进度）随 ② 做；**O1–O4（wimlib/EA 链/refscan 投放/排除 退役）在 A 引擎全链通过后执行**——之前不动，保证 B 回退完好 |

> 待 ② 完成后由救援脚本以 `engine=swap` 分支调用）。
