# 23 - 0.7 方案复审与最小自测清单（专家组，2026-10-09）

> 三问：①现在方案（A 引擎 = Windows 原生解压 + Linux 仅改名交换）在逻辑上是否最优？
> ②有哪些值得优化的地方/该抛弃的代码？③新一轮最小自测清单。

## 1. 专家组复审：A 引擎是否最优

### 1.1 候选方案对照

| 方案 | 数据写入 | 保真 | 空间 | 合规 | 结论 |
|---|---|---|---|---|---|
| **A（现方案）** | Windows 原生（wimlib Windows 路径） | 全原生（reparse/EA/ACL/时间戳） | **2×** | ✅ 不碰 WinPE | **最优（在约束内）** |
| B（封存线） | Linux 块模式 apply | 丢 EA/非微软 reparse、EFS 跳过 | 1× | ✅ | 保留为**小空间回退** |
| C（全 PE 内 apply） | WinPE 里 Windows wimlib | 同 A | 1× | ❌ **违反 §2 红线**（禁 WinPE/WinRE） | 否决 |
| D（扇区级克隆） | 裸扇区 | 全保真 | 1× | — | 不做（非本产品形态/镜像格式不兼容） |

**逻辑结论**：在"**不得用 WinPE + 已有 Linux 救援层 + 要求原生保真**"三重约束下，A 是唯一同时满足的方案；
C 看似省空间（无需 2×）但踩红线；B 的保真缺陷正是新线要根除的。

### 1.2 A 方案的逻辑漏洞审计（须在 P1/P2 堵上）

| # | 漏洞 | 对策（必修） |
|---|---|---|
| L1 | `~new` 解压**中途中断**（断电/用户取消）→ 半棵树 | **完成标记 + 报错不继续（用户 2026-10-09 定案）**：解压成功后写 `~new\.zj-done`；失败/中断 → **报错、绝不碰旧树、删除 `~new`、让用户换镜像**；断电场景由**下次 Windows 启动检测孤儿 `~new`（无标记）→ 提示并清理**；首版不做断点续解 |
| L2 | 特殊顶层项（`$Recycle.Bin`/`System Volume Information`/pagefile 等）不能简单进 `~old` | 交换清单白名单化：特殊项**删除旧+移新**或**保留旧**（P1 定案；两者都不影响启动） |
| L3 | 交换自身中断 → 半新半旧 | P1 事务化：**先把 `~new` 全部就位准备、再原子改名**；旧树在 `~old` 可回滚（P0 先记录行为） |
| L4 | 目标盘**放不下 2×** | 回退链：①目标盘 2× 不够 → ②别的分区解压 + Linux **跨区拷贝**（慢但可行）→ ③B 引擎；空间预检（`EstimateSwapSpace`）负责判定并提示 |
| L5 | UEFI 的 ESP 不在主镜像里 | 复用现有 ESP 子镜像机制：Windows 侧把 ESP 子镜像 `extract --index N --dest <ESP挂载点>`（原生写入）✓ |
| L6 | 旧树删除失败（占用/权限） | 首启删失败→登记 `MOVEFILE_DELAY_UNTIL_REBOOT` 重试（PIT-123 同名坑注意）；日志留证 |

**总评：方案逻辑成立；L1/L2 是 P2 前必须有的安全件，L3 是 P1 设计件。**

## 2. 优化机会 + 该抛弃的代码（第二批坟场候选）

### 2.1 优化（A 引擎带来的简化）
| # | 项 | 收益 |
|---|---|---|
| O1 | **救援层不再需要 wimlib/apply**：交换只需 ntfs-3g 挂载 + rename → 裁掉 initramfs 的 `wimlib-imagex`/`libwim.so`/镜像扫描/apply 段 | initramfs 更小、脚本更简单（救援=交换+引导修复） |

## 5. 运行期残留检测与分流（用户 2026-10-09 规格；实现 `src/app/swapleft.{h,cpp}`）

程序启动（GUI 建窗前 / CLI 分发前）扫描全部固定盘根的 `~new` / `~old`，按决策表处理。
一句话：**隔了较久（≥24h）直接删；刚发生的接着处理；拿不准的问用户。**

### 5.1 决策表（`DecideSwapLeftover`，纯逻辑可单测口径）

| 残留 | 条件（按序） | 动作 | 说明 |
|---|---|---|---|
| `~new` | age ≥ 24h | **Delete** | 过期孤儿/垃圾，启动即删（记日志） |
| `~new` | 近期 + 有 `.zj-done` | **Reuse** | 启动期只记日志；还原 swap 分支**比对 `content=` 与所选镜像一致**才复用（免重解压），不一致 → 删掉重解 |
| `~new` | 近期 + 无标记 | **Redo** | 启动期只记日志；还原 swap 分支执行时自动删除重新解压（替换旧的盲目 `DeleteTreeRec`） |
| `~old` | 根下**没有** `Windows\` | **AskUndo** | 任何账龄都问：交换中断态，`~old` 可能是仅存的旧系统 → **"过期直接删"对 ~old 不适用**（有意偏离，防丢数据） |
| `~old` | 同盘 `~new` 仍在 | **AskUndo** | 交换中途崩溃的典型形态 |
| `~old` | 根完好且 `~new` 已消费 | **Delete** | 交换已完成（首启清理没跑）→ 本来该删；`ZJRESTORE-status.txt result=OK` 只作 reason 佐证 |

- `ageHours = -1`（读不到时间）→ 保守视为"刚发生"，不走"过期直接删"。
- **AskUndo 的用户交互**：GUI `CConfirmDlg::Ask2`（标题「检测到还原残留」，左**「保留不动」**[默认/安全项]、右**「撤销恢复」**）；CLI 打印 `[y/N]` 询问（`--yes` 直接撤销；stdin 非控制台 → 保留不动并警告，不阻塞脚本）。
- **撤销** = `~old\*` 逐项搬回根（根下已存在同名 → 留在 `~old` 不覆盖，记日志）。
- 后台删除（GUI `DeleteSwapLeftoverAsync`）经 busy 登记；**swap 还原分支进门前 `WaitSwapCleanup`**，防并发踩踏。

### 5.2 与还原流程的接线（fail-closed）

- `StageRestoreImpl` swap 分支：`~old` 残留未处理 → **中止（rc=4）**，提示重新运行程序再询问；
  `~new` 按上表复用/重解（复用判定 = `Reuse && content==所选子镜像`）。
- `bootfiles/zjswap.sh`：**目标上已有 `~old` → 拒绝交换（exit 3）**（与 Windows 侧双保险）。

### 5.3 自测口径

| # | 测试 | 通过标准 |
|---|---|---|
| S-R1 | 造过期 `~new`（改 mtime）→ 启动 | 自动删除，日志有 `-> delete` |
| S-R2 | 造完整 `~new`（含 `.zj-done`，同镜像）→ swap 还原 | 复用免重解压（日志 `reuse existing ~new`） |
| S-R3 | 换一个镜像 → swap 还原 | `discard ... content mismatch` 后重解 |
| S-R4 | 造 `~old`（根有 Windows、无 `~new`）→ 启动 | GUI 弹框 / CLI 询问；保留 → swap 还原被 rc=4 拦住 |
| S-R5 | 造 `~old`（根无 Windows）→ 任何账龄 | 一律 AskUndo，绝不自动删 |
