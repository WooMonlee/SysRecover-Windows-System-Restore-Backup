# SysRecover · PE 直装（就地还原）验收清单

> 目的：验证**目标分区没被占用**时（在 WinPE 里、或正常系统里还原到非系统盘），
> 程序**直接就地把镜像写进去、不重启**（PIT-064）。
> 这是目前**唯一没实测过**的主路径；照下面走一遍即可闭环。

---

## 0. 一句话预期

在 PE 里把镜像还原到 C: → 界面直接走「格式化 → 应用 → 修引导」→ 弹「**还原完成，无需重启**」→
**不重启**，关机/重启后直接进新系统 ✓（对照：正常 Windows 里还原 C: 会暂存并重启走 Linux 救援 ✓）

## 1. 准备

| 项 | 要求 |
|---|---|
| PE | 任意 WinPE（64 位；本程序**仅 x64** ✗ 32 位 PE 跑不了）—— 微PE/优启通/官方 ADK 都行 |
| 程序 | `dist\` 整个目录（含 `bootfiles\`、`libwim-15.dll`、`SysRecoverUI.exe`）|
| 镜像 | 一个**万能镜像**（.esd/.wim）放在**非目标分区**（如 U 盘或 D:）✓ —— 放在目标分区里会被安全门禁拒绝 ✓ |
| 目标 | 一块**可以被随便格式化**的磁盘/分区（建议先用原 Windows 建个快照）|
| 时间 | 约 5~15 分钟（取决于镜像大小与磁盘）|

> 若在 PE 里看不到某块盘：先确认 PE 自带该控制器驱动（VMD/RAID 常见）——本程序的**救援层**驱动很全，
> 但**PE 本身**认不到盘就没法操作 ✗。

## 2. 步骤与逐步预期

| # | 操作 | 预期现象 |
|---|---|---|
| 1 | PE 里进 `dist\`，双击 `SysRecoverUI.exe`（UAC 在 PE 里通常直接过）| 窗口打开，顶栏模式为「文件→系统」（还原）|
| 2 | 点「浏览系统镜像文件」选镜像 | 第二步出现 `镜像说明：1 - <名称>`（**完整显示**，不是 `1 - W` ✓）|
| 3 | 在「系统安装位置」选中**目标分区**（如 `C GPT NTFS 当前系统 ...`）| 主按钮「开始恢复系统」**转蓝**（可点）|
| 4 | （可选）勾「静默模式」→ 全程无对话框 | 建议**先不勾**，便于看提示 |
| 5 | 点「开始恢复系统」→ 确认框选「退出并重启」| ⚠️ 这里按钮叫「退出并重启」，但**就地路径下不会真的重启** ✓（见下一步）|
| 6 | 观察进度与提示 | 进度条走 `格式化 → 应用 → 修引导`；结束后弹「**系统还原已完成，无需重启**」✓ |
| 7 | 拔掉 PE U 盘，重启 | **直接进还原后的系统** ✓ |

## 3. 判定（通过 / 失败）

**通过**（全部满足）：
- [ ] 第 6 步**没有重启**，而是弹了「无需重启」✓
- [ ] 日志里出现 `restore mode: in-place (目标分区未被占用)` ✓
- [ ] 目标分区上确实写入了镜像内容（PE 里 `dir C:\Windows\System32\winload.exe` 存在 ✓）
- [ ] 第 7 步开机进的是**还原后**的系统 ✓
- [ ] **UEFI 机器**：引导正常（ESP 上的 BCD 被 `bcdboot` 修好）
- [ ] **BIOS 机器**：引导正常（见下方 ⚠️）

**失败** → 取下节日志，按症状对号入座。

## 4. 失败时看哪里

日志（**软件目录**，即 `dist\logs\`）：
- `SysRecover-*.log` —— 主日志：`restore mode: ...` / `format.com rc=` / `bcdboot (UEFI|BIOS) rc=` / `in-place restore done` 等关键行 ✓
- `progress.json` —— 实时进度快照

## 5. 常见症状 → 对策

| 症状 | 原因 | 对策 |
|---|---|---|
| 日志是 `restore mode: staged reboot (...)` 而**不是** in-place | 卷没锁住（目标盘上有打开的文件/句柄）| PE 里关掉资源管理器/其它程序；或先 `mountvol`/`diskpart` 卸载目标卷再试 |
| `format.com` 失败 | 卷被占用 / 写保护 | 同上；确认不是 U 盘只读 |
| `apply` 失败 | 镜像不可用（半截文件/校验不过）| 先 `SysRecover.exe verify --image <镜像>`；或用 `images` 列出子镜像确认 `--index` |
| **BIOS 下重启后黑屏、左上角光标闪** | 理论上**不该出现**：就地路径用的是 **`format.com`（微软自家格式化器）**，它写出的 NTFS 引导区就是**微软引导代码**（含扇区 0 的代码段与扇区 1..8 的后续代码，PIT-049/050/053），比 Linux 侧的 `mkntfs`（占位代码）更稳 ✓ | 若真复现，再查 PBR：`dd` 读目标分区扇区 0 的 `0x54` 处应为 `fa 33 c0 8e d0 bc 00 7c`；并把日志发我 |
| UEFI 下重启进不去 | ESP 的 BCD 没修好 | 看日志 `bcdboot (UEFI) rc=`；非 0 就是失败；确认 PE 里能挂到 ESP（`mountvol X: /s`）|

## 6. 顺带可验的两条

- **正常 Windows 里还原到非系统盘**（如还原一个数据分区镜像到 D:）：
  若 D: 没被占用 → 应该也走 in-place ✓（日志同上）；若 D: 有句柄 → 回落 staged ✓（**这是预期行为**，不是 bug ✓）
- **静默模式**：勾上后整个流程**一个对话框都没有** ✓（还原 C: 会直接暂存+重启 ✓）

## 7. 回传什么给我

1. `dist\logs\` 里的 `SysRecover-*.log`（整个文件）
2. 现象描述：卡在哪一步 / 弹了什么 / 重启后进的是新系统还是老系统 / 黑屏的话屏幕长什么样
3. 环境：PE 是 32/64 位、BIOS 还是 UEFI、目标盘是 NVMe 还是 SATA
