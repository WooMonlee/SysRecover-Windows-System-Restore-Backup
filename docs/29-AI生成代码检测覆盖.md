# AI 生成代码检测覆盖评估（2026-10-24）

> 结论：不建议照搬“推理服务/Web 服务”的九阶段清单。SysRecover 是
> Windows 原生 C++ + Linux 救援层 + QEMU 救援演练，适用的检测分为
> **编译/静态门禁、单元/契约、CLI 冒烟、QEMU 集成、制品校验** 五组。
> 本轮已把缺失且可离线运行的检查接入 `make check` / 独立 target。

## 已接入

| 检查 | 命令/位置 | 覆盖 |
|---|---|---|
| 编译 + 双架构链接 | `make package`、CI x64/x86 | 头文件、签名、链接、x86 UCRT |
| 单元测试 | `make check`（58 用例/459 断言） | 纯逻辑、契约、i18n、重解析点/EA |
| Cppcheck / ShellCheck | CI `static` | C++ 静态分析、救援 shell |
| 配置门禁 | `python tools/check-config.py`（`make check`） | skin/theme XML 可解析、控件 ID 不重复、pos 合法 |
| 分层依赖 | `python tools/check-layers.py`（`make check`） | common/disk/wim/boot/app/cli/gui/tools 反向依赖 |
| 密钥扫描 | `python tools/check-secrets.py`（`make check`） | 私钥头、AWS/GitHub/Google/Slack/OpenAI token |
| 文档/契约指针 | `tools/check-docs.py`（`make check`） | 版本、contract_version、救援读取键 ⊆ Windows 写入键 |
| CLI 冒烟 | `make smoke-cli`（CI x64） | version/help/未知命令/无参数退出码 |
| 救援层 QEMU | `make drill`、`run-swap-drill.ps1`、`run-undo-drill.ps1`、`run-autorecover-drill.ps1` | B 引擎、A 引擎交换、返回旧系统、失败自动重启 |
| 制品门禁 | `make dist-check`、`make sha256` | 必需文件、version.json、无 logs/dump、SHA256 |
| GUI 外观/交互 | `tools/ui/shot.ps1`、`tools/ui/tooltip-smoke.ps1` | 原生窗口截图、Tab/按钮、tooltip |

## 评估后不适用或暂不做

| 清单项 | 结论 |
|---|---|
| mypy/Roslyn 类型检查 | 项目是 C++；编译器 + Cppcheck 已覆盖；clang-tidy 未引入，避免新增工具链 |
| OpenAPI/Playwright | 不提供 HTTP 服务、没有网页前端；对应的是文件契约测试 + 原生 GUI 截图/点击 |
| SCA/CVE（npm/pip） | 第三方是随包二进制（libwim/内核/GRUB/shim），当前无包管理清单；需联网 OSV/CVE 数据，暂不纳入离线门禁 |
| 内存/显存泄漏循环压测 | 无推理服务/显存；低内存边界已由 QEMU 512MB/192MB 演练覆盖，长期泄漏需真机采样，暂不自动化 |
| 混沌测试（端口/模型权重） | 对应场景是磁盘满、镜像损坏、UAC 取消、断电；已有失败黑匣子和自动恢复演练，未做统一故障注入框架 |

## 使用顺序

```powershell
mingw32-make -f Makefile check       # 静态门禁 + 单元/契约
mingw32-make -f Makefile package     # 双架构 + 资源
mingw32-make -f Makefile smoke-cli   # 无需磁盘的 CLI 冒烟
mingw32-make -f Makefile dist-check  # 制品完整性（会清 dist\logs）
mingw32-make -f Makefile sha256      # 发布 SHA256
```

QEMU 集成测试需要先按各脚本头注释准备/重建 `tools/vmtest/base/drill.raw`；
真机矩阵（Win7/Win10/Win11/PE、RAID/VMD、BitLocker/4Kn 等）仍需人工执行。
