## 1. 文件一览

| 文件 | 位置 | 方向 | 用途 |
|---|---|---|---|
| `restore-task.conf` | 软件目录（副契约） | Win → Linux | 还原任务参数（key=value） |
| `restore-task.json` | 软件目录 | Win → Linux | 同上 JSON 形态 |
| `_zjresy*.log` | **目标分区根**（主契约） | Win → Linux | 让 Linux 侧"发现"本次还原及其目标 |
| `progress.json` | 软件目录 `logs/` | Win → 外部 | 实时进度（供 AI/外部工具读） |
| `menu.lst` | 恢复分区根 | Win → GRUB4DOS | BIOS 菜单（`kernel` + `initrd`，**不是 GRUB2 的 `linux`**） |
| `grub.cfg` | ESP 的 `EFI\ZJRESTORE\` | Win → GRUB | UEFI+SB 菜单 |

### 1.1 `restore-task.conf`（key=value，UTF-8）

```
action=restore
pt_type=mbr|gpt
image_part_guid=<镜像所在分区的 GPT GUID>
image_rel_path=<镜像在分区内的相对路径>
image_path=<镜像绝对路径（回退用）>
image_index=<子镜像序号，1-based>
target_guid / target_offset / target_size
target_disk_serial / target_disk_name / target_disk_size
target_vol_label / target_fs
repair_boot=0|1
partition_count=<分区数>
software_dir=<软件目录（日志落这里）>
```

### 1.2 `_zjresy*.log`（主发现契约，写在**目标分区根**）

Linux 侧**不需要**去猜目标是谁：**日志写在哪个分区，那个分区就是目标**（PIT-040）。
字段：`action / log_time / software_version / software_path / target_disk_name /
target_disk_serial / target_disk_size / target_part_offset / target_part_size /
target_fs / target_vol_label / image_path / image_index / repair_boot / pt_type`。

> 为什么不按 offset/UUID 匹配：`blkid -s PART_ENTRY_OFFSET` 返回**512 扇区数**，而契约里的
> `target_part_offset` 是**字节数**，两者恒不相等（PIT-040）；UUID 也有代码页/大小写坑。

### 1.3 `progress.json`

```json
{ "Phase": "restore", "Percent": 42, "Status": "running",
  "Detail": "写入 2.1/4.0 GB", "UpdatedAt": 1755000000, "Pid": 1234 }
```

## 2. 一次还原的时序（重启路径）

```
Windows: 安检 → 镜像可用性 Probe → 写 _zjresy*.log(目标根) + restore-task.*(软件目录)
         → 部署引导层 → 设单次启动(bootsequence / BootNext) → 提示重启
   ↓ 重启
Linux  : /init (PID1) → 加载模块 → 枚举分区 → 找 _zjresy*.log → 定位目标
         → 格式化 → wimlib apply（带进度条）→ 修引导 → 写日志 → reboot
   ↓ 重启
Windows: 进入还原后的系统
```

## 3. 就地还原（不重启，新增于 2026-09-19）

目标分区**未被占用**时（在 PE 里、或还原到非系统盘），Windows 侧直接：
`format.com /Q` → `WimEngine::Apply`（目录模式）→ 仅系统镜像才 `bcdboot` → **完成，不重启**。
判据：① 目标不是正在运行的系统盘；② 能对卷加独占锁 `FSCTL_LOCK_VOLUME`。详见 PIT-064。

## 4. 进度与日志（用户可见性）

- **Windows 侧**：控制台一行刷新 / GUI 进度条 + `已用 mm:ss` + 百分比。
- **Linux 侧**：救援脚本 `wim_progress()` 把 `wimlib` 的 `(NN%)` 渲染成 `[####----] NN%` 并
  `\r` 原地刷新，同时写日志；**屏幕输出一律 ASCII**（内核字体无中文）。
- 失败时：引导期日志留在目标根（= 引导阶段没走完的信号）；软件目录 `logs/` 用于排错。
