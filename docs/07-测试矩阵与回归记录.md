## 1. 测试矩阵

| 维度 | 取值 |
|---|---|
| 固件 | BIOS/MBR、UEFI/GPT（Secure Boot 关）、UEFI/GPT + Secure Boot 开 |
| **宿主架构** | **仅 x64**（32 位 Windows / 32 位 PE 需另出 x86 版 —— x64 exe 在 32 位系统上由系统直接拒绝，2026-09-20 用户实测确认）|
| 宿主 | 正常 Windows 10/11、**WinPE**、Windows 7（需 UCRT） |
| 目标 | 系统盘（重启路径）、非系统盘 / PE 内（**就地路径**，不重启） |
| 层级 | smoke（能起救援）/ stage（暂存不重启）/ full（真重启进 Linux 全链） |
| 存储 | SATA/AHCI、NVMe、virtio、服务器 RAID（待补驱动） |

## 4. 每条链路的"关键验证点"（回归时别漏）

- **Rescue 能起来**：串口/屏幕出现 `SR: modules loaded` + `SR: block devs: …`。
- **找得到目标**：`SR: found log: /tmp/zj_M/_zjresy*.log`（主契约在目标分区根）。
- **apply 成功**：`apply rc=0`；失败时看 `/tmp/apply.out` 前 10 行。
- **引导修好**：BIOS → `PBR boot code written+verified (0x54 = fa33c08e)`；UEFI → ESP 的 BCD 未被破坏。
- **UEFI 屏显**：横幅 + `[####----] NN%` 进度条可见（否则查 fbcon/simpledrm）。
- **重启回系统**：进的是**新系统**（不是原系统）—— 万能镜像场景尤其要确认。

## 5. 已知回归雷区（踩过就别再踩）

| 症状 | 原因 | 参考 |
|---|---|---|
| 黑屏像卡死（UEFI） | 无 fbcon（需 `simpledrm`） | PIT-061 |
| 停在 `EFI stub: Loaded initrd…` | 同上（内核在跑，只是没屏） | PIT-061 |
| 还原后黑屏起不来 | 热备漏了注册表事务日志 `.LOG1/.LOG2` | PIT-056 |
| `rc=84 WIM_IS_INCOMPLETE` | 镜像上次没写完（半截文件） | PIT-057 |
| `该值受安全引导策略保护` | SB 开启时改 `nointegritychecks` | PIT-065 |
| `error: bad shim lock signature` | 内核未签名而 GRUB 强制校验 | PIT-066 |
| `module X not found in modules.dep` | 内建模块（正常）或 `modules.dep` 被 CRLF 污染 | PIT-066 |
| NVMe 每 N% 卡 30s | 虚拟 NVMe 丢完成中断，`nvme_core.io_timeout` 太大 | PIT-055 |
| 开机黑屏光标闪（BIOS） | NTFS 引导区不完整（缺扇区 1..8 / 代码段错位） | PIT-049/050/052/053 |
