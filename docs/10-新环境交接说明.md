| msys64（`zstd` / `openssl` / `sh` + **QEMU/OVMF**）| `D:\Prog\ProgIDE\msys64` | `tools/build-debian-rescue.py`（zstd 全路径）、`tools/vmtest/*.ps1`（qemu + edk2 fd 全路径）|
| 项目自身 | 建议仍放 `D:\Prog\_Project\SysRecover` | 少量相对路径假设 |

**两种做法**：① 在笔记本上**照原路径放**（最省事 ✓，推荐）；② 全局替换这几处路径（改动很小，都在上面列的位置）。

```bash
# 1) 先确认工具链在位
D:\Prog\ProgIDE\mingw64\bin\g++.exe --version

# 2) 编译 + 打包

# 5)（可选）重建救援层（需要 dl\ 里的 apk/deb，或联网重下）

```

## 6. 坑（新环境务必先看，全部踩过）

1. **`.ps1` 必须纯 ASCII**：PowerShell 5.1 把无 BOM 的 `.ps1` 按 ANSI 解析，**中文注释会把解析器打挂**
   （症状很怪，比如某个变量莫名其妙是空的）—— 本仓库踩过两次，见 `AGENTS.md` §15。
2. **不要用 `Set-Content -Encoding UTF8` 改 shell 脚本**：会加 **BOM** ✗ → `#!/bin/sh` 前面多个 BOM →
   内核执行 `/init` 失败（症状：救援层起不来）。要用 `[IO.File]::WriteAllText(..., UTF8Encoding($false))`，
   或直接用编辑工具改。
3. **`.gitattributes` 强制 `*.sh eol=lf`** ✓：shell 脚本绝不能变成 CRLF（克隆后救援层会跑不起来）。
4. **`zstd` 与 QEMU 的路径写死**在 `tools/build-debian-rescue.py` 与 `tools/vmtest/*.ps1` 里（见 §1）。
5. **push 需要梯子**（否则 `Connection reset`）。
6. **程序目前只出 x64**：32 位 Windows/PE 上 exe 由系统直接拒绝（程序内无法提示）→ `0.3` 计划出 **x86 单包**，见 `docs/08` §0。
